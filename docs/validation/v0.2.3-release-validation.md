## v0.2.3 behavioral evidence

- The scan-root boundary accepts a native absolute path returned by the folder dialog only when `ProjectSettings.localize_path()` resolves it below the active project root.
- The same boundary rejects absolute paths outside the project, `user://` paths, and parent-traversal attempts.
- The public scanner normalizes its own input rather than relying on the dock to pre-normalize it.
- The folder dialog uses resource access while retaining defensive normalization for native-dialog behavior.
- A regression test covers absolute project-path selection and a full scan through the public scanner boundary.
- Deterministic add-on packaging and release-patch generation are source-controlled and documented.
- Patch verification applies into the Git index and compares the reconstructed tree object, covering added, modified, and deleted paths.
- Git hooks and GitHub workflows use pinned `gdtoolkit` and `pre-commit` versions.
- Review-only documents were removed from the public repository; narrow product decisions and required third-party attribution remain.

## Release-integrity evidence

The release process builds deterministic full-project and add-on archives, creates a binary-capable patch from the immediately preceding tag, verifies that patch in a detached worktree, emits a review-oriented text patch and diffstat, and records SHA-256 checksums. Generated editor caches and `dist/` outputs are excluded from release inputs.

## Residual limitations

No independent unfamiliar-user comprehension, formal accessibility conformance, independent human line-by-line audit, or external security assessment was performed. The local environment had no package-network access, so `gdlint` and `gdformat` execution is deferred to a developer environment or GitHub Actions. Unsupported static-analysis boundaries remain documented.
